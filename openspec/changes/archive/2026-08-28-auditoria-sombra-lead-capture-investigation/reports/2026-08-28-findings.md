# Findings: does Auditoria Sombra leave a lead trace before the discovery call?

**Change:** `auditoria-sombra-lead-capture-investigation` (Subdomain 2 of the freemium-onboarding
master plan) · **Date:** 2026-08-28 · **Type:** investigation only, no code changed.

## Short answer

**It depends which layer you ask.** The backend Python function is genuinely stateless. But the
real product — the `contexia-wizard` app a prospect actually uses — already saves the result to
Supabase and emails the team. **Today, in production, no lead is silently lost.**

## The two layers

| Layer | Persists anything? | Where |
|---|---|---|
| Backend (`apps/backend`, `run_auditoria_sombra`) | **No.** Pure compute-and-return. | n/a |
| Frontend (`contexia-wizard`, the actual GTM tool) | **Yes.** Every completed audit. | Supabase `leads` table + internal email |

- Backend: `run_auditoria_sombra` (`apps/backend/services/wizard_service.py:132-209`) builds a
  synthetic profile, runs Centinela's rules in-memory, calls an LLM for narrative synthesis, and
  returns a dict. No DB call, no queue, no file, anywhere in that chain. Confirmed by direct
  reading, not just subagent summary.
- Frontend: `contexia-wizard`'s `Step8Diagnostico.tsx` calls the backend, then immediately calls its
  *own* server route (`app/api/audit/execute/route.ts`), which writes `audit_result`,
  `audit_executed_at`, `status: "audited"`, and `lead_score` into Supabase `leads` — an
  insert-or-update, unconditionally, on every successful audit — and sends the sales team an
  internal email with the prospect's risks, potential savings, and a WhatsApp follow-up link.

## Why this matters for the plan

Subdomain 5 (`freemium-tenant-minimum-seed`) was scoped assuming a gap that, for the flow as it
ships today, doesn't exist — the sales team already has both a DB row and an email per completed
audit. Building new persistence there would duplicate what already works, or worse, create two
competing write paths for the same lead.

**What still needs a decision before Subdomain 5 proceeds:**
1. Will the freemium entry point actually be `contexia-wizard` (already covered), or a different
   surface calling the backend directly (would need its own persistence, since the backend has none
   built in)?
2. The persisted `audit_result` is the LLM-merged summary, not the raw Centinela alerts — if
   Subdomain 3's plan-tier gating needs the structured alerts, `CentinelaService.save_alerts()`
   still needs to be wired in; it is never called today, by either layer.
3. The existing write has no retry or alerting on silent failure (Supabase write errors return a
   generic 500; the email failure is caught and only logged). Worth a founder call on whether that
   reliability bar is good enough for a paid-track feeder funnel.

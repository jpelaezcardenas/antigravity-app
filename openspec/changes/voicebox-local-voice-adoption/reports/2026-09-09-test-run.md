## Environment findings (pre-existing, unrelated, worth their own change)

1. **`TestClient` is broken repo-wide.** httpx 0.28.1 removed the `app=` shortcut that starlette
   0.27.0's `TestClient` still passes, so `TestClient(app)` raises
   `TypeError: Client.__init__() got an unexpected keyword argument 'app'` for every test in the
   repo. The voice tests await endpoint coroutines directly instead, which exercises the same
   functions the router calls.
2. **Importing the backend costs ~5 minutes.** Module import triggers KB/pgvector seeding that
   tries every embedding provider and waits out their timeouts
   (`KB[pgvector]: skipped 48/48 chunks ... all providers unavailable`). Measured directly:
   `import presentation.whatsapp_endpoints` = 285 s. This is import-time network I/O, so it also
   affects cold starts, not just tests.

Both are recorded as follow-ups FU.2 and FU.3 in `tasks.md`.

## Stage 10 — manual endpoint testing (executed)

Backend booted locally with `apps/backend/.venv`, `INTERNAL_API_KEY=stage10-local-test`,
`VOICE_ENABLED=false` (the production-like state), on `127.0.0.1:8099`.

| Check | Command | Expected | Got |
|---|---|---|---|
| Route mounted in the **assembled** app | `GET /openapi.json` | path present | ✅ `/internal/whatsapp/voice-note` listed, alongside `/internal/ingest/file` and `/internal/siigo-sync/run` |
| No auth header | `POST` without header | 401 | ✅ 401 `{"detail":"Invalid internal API key"}` |
| Wrong key | `POST` with `X-Internal-Api-Key: wrong-key` | 401 | ✅ 401 |
| **Feature switched off** | `POST` with the correct key | 503 | ✅ 503 `{"detail":"Voice is disabled"}` |
| Auth precedes the flag | wrong key **and** flag off | 401, not 503 | ✅ 401 — the flag state does not leak to an unauthenticated caller |
| Request model wired | `POST {"lead_id":"x"}` | 422 | ✅ 422 |
| Method restricted | `GET` on the route | 405 | ✅ 405 |
| Sibling internal routes still work | `POST /internal/siigo-sync/run`, `POST /internal/ingest/file` | reachable | ✅ both 422 (body validation) — the fail-loud registration change did not break them |

This is what `curl` adds over the unit tests: proof that the router is genuinely **mounted** in the
assembled application, which no unit test can show, and proof that removing the swallowing
`try/except` did not drop the two pre-existing internal routes.

**One check produced an unexpected result, and it is worth recording rather than hiding.**
`POST /api/v1/channels/whatsapp/leads/fake/reply` with no auth returned **500**, not 401:

* No 401 because `AUTH_ENFORCED` defaults to `False`, so auth is permissive in this local env. The
  test expectation was wrong for a local run, not the code.
* The 500 is `postgrest APIError 22P02: invalid input syntax for type uuid: "fake"` — `lead_exists()`
  passes a non-UUID straight to Postgres. **Pre-existing** in `taty_lead_reply`, on a code path this
  change does not touch. Recorded as follow-up FU.5, because the new voice endpoint calls the same
  `lead_exists()` and would behave the same way; it was deliberately left consistent with the
  existing endpoint rather than fixed in one of the two places.
